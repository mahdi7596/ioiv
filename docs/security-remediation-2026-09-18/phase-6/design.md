# Phase6 R4 design and QA inventory

Authorized scope: both OTP POST routes. Require a configured absolute http(s) APP_URL with no credentials, query, fragment or non-root path; permit HTTP only for loopback local qualification/development, require HTTPS elsewhere. Use its canonical URL origin, never request URL, Host, Forwarded or X-Forwarded-* for trust. Require exact serialized browser Origin match; reject missing/null/foreign/multiple/malformed Origin with403 before reading body. Require application/json (case insensitive, optional UTF-8 charset) with415 before reading body. Invalid config fails closed503 with safe Persian copy. Invalid JSON400, no body/provider/OTP logging. No nonbrowser exemption, CORS relaxation, schema, grants, retention or business change. Existing clients already send JSON via same-origin fetch.

Documented nginx listens on80 and forwards HTTP; actual TLS ingress is unqualified. The local fixture terminates TLS and forwards HTTP with original Host/X-Forwarded-Proto; preserve browser Origin and compare against configured HTTPS APP_URL regardless of internal scheme. Actual production proxy unavailable/unqualified; test a loopback HTTPS reverse proxy with ephemeral self-signed certificate, production Next process and restricted PostgreSQL. No production claim.

QA: historical foreign top-level text/plain form with fresh synthetic attacker code must reproduce cookie on unchanged Phase5, then403/no cookie/unchanged OTP, user and admin; null-origin sandbox form, same-origin wrong media, malformed JSON, spoofed Host/forwarded headers, absent Origin, wrong scheme/port and invalid config all fail before actions. Unit spies prove no parsing/action. Real DB snapshots prove no quota/OTP/user/session side effects. Normal applicant/admin390/1440 controls request code and verify through HTTPS with actual Secure/HttpOnly/Lax cookie and dashboard; errors visible, no overflow, screenshots inspect. Two Next processes reject concurrent hostile requests. Unavailable DB still rejects hostile request before DB; valid request503. Full suite including real DB, process regressions, types/lint/build and independent critical review. No later phase work.

Rollback: retain existing expanded DB and protections; drain auth writers and deploy compatible guard version, never revert to vulnerable routes. No migration or existing-data repair. D1/D2/D3 settled.
