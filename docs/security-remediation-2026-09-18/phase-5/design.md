# Phase 5 R5 design — authorized local work only

D1/D2/D3 settled. Reuse AuthVerifyBucket storage, pruning, shared advisory lock and dedicated secret with distinct request namespace; verification budgets remain separate. One DB admission instant drives hourly HMACs and exact rolling events. Mobile+purpose: 90 seconds and five/hour. Trusted address and shared unknown each use configured OTP_MAX_REQUESTS_PER_IP_PER_WINDOW (default30, valid1–3000). Global3000/hour bounds allocation. Address/global denials count before mobile/admin lookup. Existing admin403 remains Phase7, Origin/CSRF remains Phase6.

Add AuthRequestIntent containing UUID, hourly HMAC mobile key, admission timestamp and nullable dispatch claim timestamp only. Admission commits intent and quota before bcrypt. Claim transaction checks fresh90-second lifetime, claims once, invalidates old code and inserts new OTP atomically. Commit must be acknowledged before one awaited, bounded SMS call. No retries/refunds after rejection, uncertainty, crash or lost commit acknowledgement; subsequent explicit requests obey cooldown/hour quota. No recoverable plaintext OTP. Expired delayed work cannot supersede later reservations. Raw request IP is no longer persisted for new OTPs.

Cleanup deletes intents older2hours using narrow helper; hourly existing maintenance runs both helpers. Request admission/claim fails closed on cleanup/config/DB failure. Hourly pseudonyms plus current/previous accounting retain Phase4 healthy retention under24h; no changed backup/WAL promise. Additive migration/grants, no historical repair; pause/drain auth writers at rollout and retain schema on rollback, never overlap old vulnerable request writers.

Acceptance: eight concurrent requests admit one; separate-process restart/crash preserves caps and once claim; real restricted PostgreSQL rolling boundary, failures, stale work, cleanup/permissions and migration recovery. Controlled loopback SMS/browser tests prove slow/failure/timeout and no duplicate dispatch, no secret logging. Regression, types/lint/build and independent critical reviews. No production/live provider action, no later phase.
